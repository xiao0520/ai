# 合同智能体第一版实现说明

第一版实现合同上传、信息提取、风险审查和结果查看，保持一张业务表、一个固定 LangGraph、两个用户接口和一个用户页面。复用现有 Agent、模型权限、知识库授权、RAG、OSS、内部签名和异步线程池。

## 使用前准备

1. 对存量库执行 `main-service/docs/script/sql/contract-review-v1.sql`。全量初始化 SQL 已同步；已有任务表时会幂等补充 `billing_json`、`operation` 字段，不覆盖已有任务数据。
2. 在已有 Agent 管理中创建合同智能体，编码填写 `contract-review`。绑定用户有权使用的默认聊天模型、已就绪的合同审查知识库，并配置 Agent 访问权限。
3. 默认聊天模型需要支持工具调用形式的结构化输出。扫描件识别复用该智能体授权范围：可使用支持 `IMAGE` 输入的默认聊天模型，或在可选模型模式下只绑定一个图片识别模型；存在多个图片模型时拒绝自动猜选。模型、端点和凭证别名继续由模型管理下发，真实密钥仍保存在 Python 部署配置。
4. 为用户配置正常状态的 Token 账户与额度；额度不足时不允许提交模型调用。不限额账户同样登记用量。
5. 重启 Java、Python 服务并更新用户端。登录后从“智能体”进入合同页面，选择“智能审查”或“信息提取”。审查支持 PDF/DOCX；独立提取还支持 PNG/JPEG 和扫描 PDF。

本次未直接执行数据库迁移，也未改动管理员已有 Agent/模型/知识库配置。

## 配置合同审查提示词

在后台 Agent 管理中编辑编码为 `contract-review` 的合同智能体，填写现有“自定义提示词”并保存。该字段复用 `systemPrompt`，不新增配置页或数据库字段。保存后的配置用于下一次新建审查任务，不修改已经运行或完成的任务。

提示词只补充风险审查的业务重点，例如：

> 从采购方立场审查，重点关注预付款、交付验收、违约责任及解除权，指出责任明显不对等的约定。

合同事实提取仍仅依据原文，不受这段配置影响。固定的原文引用、证据来源、禁止编造和结构化输出约束保留；审查立场与任务表单冲突时以本次表单选择为准。配置作为业务要求拼入审查输入，不能代替固定系统规则或开通新工具权限。

不填、清空或仅填空白时沿用默认审查。长度沿用聊天消息的 20000 字符协议上限，实际输入还受模型和账户 Token 预算限制；配置内容会正常参与 Token 计量，不会绕过扣费。本次接入只需同步部署 Java、Python，无须额外数据库迁移或重建前端。

## 执行与存储

智能审查：`上传 → Java 校验权限及文件 → OSS/任务保存 → Python 解析 → 信息提取 → 授权 RAG → 风险审查 → 结果校验 → Java 保存 → 页面展示`

独立提取：`上传 → Java 校验权限及文件 → OSS/任务保存 → 文本解析/扫描页 OCR → 信息提取 → 结果校验 → Java 保存 → 页面展示`

两种模式复用同一个任务表、接口、LangGraph 和结果协议，通过 `operation=REVIEW|EXTRACT` 分支；提取模式不创建知识库范围、不执行检索和风险审查。扫描 PDF 按原页渲染并逐页识别，当前上限 20 个扫描页/图片；超限、输出截断或部分页面识别失败时任务整体失败，不保存为完整结果。

任务状态只有 `RUNNING`、`COMPLETED`、`FAILED`。任务创建时即进入执行状态；结果以版本化 JSON 整体保存。成功、失败均用条件更新保护终态，长连接期间不持有数据库事务。

原始文件保存到现有 OSS 业务目录，Python 通过本次签名 multipart 请求取得文件，执行后删除临时副本。此版采用直接传输，未增加合同文件票据接口。上传上限和业务目录沿用现有 `ai.knowledge.upload.max-size-mb`、`ai.oss.knowledge-attachment.config-key` 参数。

单次执行遵守模型输入/输出、账户批准总预算及最长 300 秒执行策略。浏览器断开不取消已提交任务，Java 继续接收内部执行结果并结算，用户可按原任务地址查询。Java 与 Python 内部连接断开时，Python 停止可取消调用并清理资源；服务重启遗留任务在执行期限加 30 秒缓冲后查询收口，按已持久化快照结算。

## Token 扣费

- 信息提取、扫描页视觉识别和风险审查分别计量，RAG 的查询向量化与重排也计费，复用现有 `user_token_account` 和 `token_usage`，不新增计费表。
- Java 在任务创建时预占额度；Python 在每次调用前检查剩余预算，输出上限随可用余额收紧。阶段与等待期间上报累计用量，Java 保存到任务的 `billing_json`。
- 优先采用供应商实际 Token，标记 `ACTUAL`；未返回 Token 的视觉识别按实际图片尺寸和输入文本估算，未返回 Token 的重排按实际查询和候选文本估算，均标记 `ESTIMATED`。生成与文本向量化缺少计量时同样保留估算，不按零用量跳过。
- 任务成功、失败均结算已发生调用并释放未消耗预占；明确的认证、参数或限流拒绝不计消耗。网络中断且无回执时只保留已提交输入的估算，不能声称其等于供应商最终账单。
- 任务行锁保护终态，用量流水、账户结算和任务终态在同一事务提交。重复终态不重复扣费。供应商实际值超出预算时尝试补占差额；余额不足则保留任务和用量快照供管理员核对，不截断用量或静默返还额度。
- 本次也补齐共享 RAG 正常调用的重排 Token 计量及预占，多个索引共用一个向量模型时，按实际可能发生的调用次数预占。

进程被强制终止或内部网络彻底中断时，只能恢复最近保存的用量快照；这一版未实现供应商账单对账，极短上报窗口内的消耗不能保证完整恢复。

## 结果与扩展

结果包含合同主体（甲方、乙方、其他主体）、金额与币种、合同期限、生效和起止日期、付款、交付验收、违约、终止和争议解决约定。审查模式额外返回风险等级、分类、原文、位置、建议和知识依据；独立提取模式的风险项和风险汇总固定为空。合同原文和模型输出均按纯文本展示。

风险引用必须在合同中唯一匹配，否则忽略该项并返回提示。模型不能生成有效引用的项目不会显示为确定风险。无知识命中时可以给出基于原文的条款分析，但不能虚构法规或制度来源。

后续增加风险检查，优先修改审查提示词和归一化规则；需要独立步骤时增加 Graph 节点。新增解析格式可替换解析器，新增结果字段通过版本化 DTO/Schema 演进。只有出现逐风险筛选统计需求时，才考虑拆明细表。

第一版支持 PDF、DOCX 的原生文本提取，并在独立提取模式支持扫描 PDF、PNG、JPEG 的受限 OCR；不含手写体专项识别、问答、审批、合同自动修改、报告导出、任务列表或断点恢复。OCR 结果会明确提示核对主体、金额和日期。计费复用现有 Token 账户；数据库真实事务、账户并发和真实模型消耗仍需部署环境联调。

## 验证

Python 包含 Graph 和内部接口测试，覆盖授权签名、结构校验、保活、失败终态、原文定位及临时目录清理。Java 测试覆盖共享契约往返、非法结果拒绝、任务归属和异常终态；前端运行定向 ESLint、类型检查及构建。

本次验证结果：

- 合同 Python 定向回归 32 通过，覆盖独立 Graph 分支、PNG/JPEG、真实扫描 PDF 渲染、页码、视觉模型缺失、无法识别、输出截断、实际/估算 Token 保留和临时目录清理；定向 Ruff、Mypy、合同 Schema 同步检查通过。
- Java 合同服务、持久化和计费定向测试通过，覆盖提取模式不创建知识库范围、视觉模型授权、视觉/生成分开记账以及提取成功只要求一次结构化生成调用。账户真实事务回滚和真实供应商账单仍需部署环境联调。
- 用户端 TypeScript、定向 ESLint 和生产构建通过。构建仍有项目既有的 KaTeX 字体运行时解析提示，不影响本次页面打包。
- 当前全量 Python 回归为 323 通过、5 跳过、10 失败；Java 全量测试为 261 个用例中 3 失败、10 错误、2 跳过。失败集中在同一工作区正在调整的共享 RAG 契约、旧生成类/样例和对应测试，并非合同定向链路；交付合并前仍需完成该共享改动的统一收口。

本轮执行命令：在 `ai-service/` 使用项目虚拟环境运行合同相关 `pytest`、定向 `ruff check`、定向 `mypy` 和 `scripts/export_contract_review_contract.py --check`；在 `main-service/` 使用项目 JDK 21 运行合同相关 Maven 测试；在用户端运行 `vue-tsc`、定向 ESLint 和 `pnpm run build`。

实际验证的依赖为 LangGraph 1.2.12、langchain-openai 1.6.0、FastAPI 0.141.1、Pydantic 2.13.4。结构化输出适配依据 [ChatOpenAI.with_structured_output 官方文档](https://reference.langchain.com/python/langchain-openai/chat_models/base/ChatOpenAI/with_structured_output)，使用 `function_calling` 模式。

计量字段核对了 [LangChain ChatOpenAI 用量说明](https://docs.langchain.com/oss/python/integrations/chat/openai)、[百炼重排接口](https://help.aliyun.com/en/model-studio/text-rerank-api)和[火山重排接口](https://docs.volcengine.com/docs/vector_database_vikingdb/Rerank-2?lang=en)。结构化调用保留 `include_raw=True` 的原始回执，先记录用量，再校验业务结果。

真实模型审查效果需在迁移和 Agent 配置完成后，用脱敏合同进行联调，并由业务人员确认审查结果。
