# 聊天执行链路配置

用户端只调用 Java 的 `POST /chat/send`。Java 校验登录态、会话归属、角色模型权限和 Token 额度，再将签名后的内部请求转发到 Python：`POST /internal/ai/v1/chat/stream`。

Python 不连接业务 MySQL、不接收浏览器 Token，也不保存会话、消息或额度。模型 API Key 仅保存在 Python 环境变量中；Java 只传递模型发布快照及 `credentialKey`。

## Java 环境变量

在启动 Java 服务的运行环境中设置以下变量：

```text
AI_PYTHON_BASE_URL=http://127.0.0.1:8000
AI_INTERNAL_SERVICE_TOKEN=<至少32位随机值>
AI_INTERNAL_SIGNING_KEY=<至少32位随机值>
AI_PYTHON_CONNECT_TIMEOUT=10s
AI_PYTHON_REQUEST_TOTAL_TIMEOUT=300s
AI_CHAT_HISTORY_MAX_MESSAGES=20
```

`AI_INTERNAL_SERVICE_TOKEN` 与 `AI_INTERNAL_SIGNING_KEY` 必须和 Python 使用完全相同的值。它们为空时 Java 会拒绝启动，避免把内部接口暴露为匿名调用。

## Python `.env`

从 `D:\project\ai-service\.env.example` 复制变量名到 `D:\project\ai-service\.env`，并填写实际值：

```text
AI_ENVIRONMENT=dev
AI_INTERNAL_SERVICE_TOKEN=<与Java相同>
AI_INTERNAL_SIGNING_KEY=<与Java相同>
AI_INTERNAL_AUTH_MAX_AGE_SECONDS=300
AI_PROVIDER_TIMEOUT_SECONDS=60
AI_PROVIDER_KEEPALIVE_SECONDS=10
AI_PROVIDER_CREDENTIALS={"doubao":"<豆包API Key>","deepseek":"<DeepSeek API Key>","zhipu":"<智谱API Key>"}
```

`AI_PROVIDER_CREDENTIALS` 是凭证别名到实际 API Key 的 JSON 映射，可以同时配置多家厂商，也可以为同一厂商配置多个别名。管理端模型的 `credential_key` 只引用这里的别名，不保存明文密钥。

当前 Python 聊天 Provider 注册表支持以下经过官方文档核对的 OpenAI 兼容厂商：

| `provider_code` | 管理端 `api_host` | 示例 `credential_key` |
| --- | --- | --- |
| `doubao` | `https://ark.cn-beijing.volces.com/api/v3` | `doubao` |
| `deepseek` | `https://api.deepseek.com` | `deepseek` |
| `zhipu` | `https://open.bigmodel.cn/api/paas/v4` | `zhipu` |

模型名称以各厂商控制台当前提供的调用标识为准，由 Java 发布模型快照下发。Python 按 `providerCode` 选择 Provider 策略、按 `credentialKey` 选择密钥；两者职责独立。未注册厂商返回 `MODEL_UNAVAILABLE`，不会把任意地址当成兼容接口尝试调用。

## 事件与记账

Python 返回 `delta`、`usage`、`completed`、`failed`、`keepalive` 五类 SSE 事件。Java 转换为用户端当前的 `content`、`error`、`done` 事件，并在终态写入：

- `chat_message`：用户消息、助手消息或失败审计；
- `chat_session`：消息数、最近模型和累计 Token；
- `token_usage`：每次调用的成功/失败用量明细；
- `user_token_account`：调用前预占最大上下文额度，完成后按模型返回的真实 Token 结算，失败时释放预占。

额度不足、模型未授权、会话非本人或会话已归档都会在 Java 侧被拒绝，Python 不参与这些业务判断。
