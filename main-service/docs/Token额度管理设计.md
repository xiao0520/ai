# 公司内部 AI Token 额度设计

> 现行实现核对：2026-09-28。Java 已接入普通聊天、RAG 查询/生成及 MCP 多轮模型调用的预占与结算。本文保留业务规则和现行边界；表结构与事务实现以 [ruoyi-ai.sql](script/sql/ruoyi-ai.sql)、增量迁移及 Java Token Service 为准。旧“仅 Java 配置管理、Python 尚未接入”的阶段描述已废弃。

## 业务规则与数据所有权

员工通过角色获得可用模型；多个角色授权取有效并集，Agent 绑定不能越权。多个模型默认共用员工全局 Token 账户。管理员可分配、追加、设置剩余、冻结或配置不限额，变更和调用均留审计。AI 成本用于内部统计，不建立支付或财务账单。额度账户、预占和实际扣减以 Java/MySQL 为唯一权威；Python 不访问或修改额度业务表。

实际模型用量与扣减额度分别记录。模型返回的输入/输出 Token 用于真实使用量，受账户规则约束的 `charged_tokens` 用于余额；不限额账户仍记录真实用量。UNKNOWN 用量不能默认为免费。知识库入库、查询 Embedding/Rerank 与聊天生成的用量类型和结算入口不同，不得把 REQUESTS、DOCUMENT_PAIRS 直接当作 CHAT Token。

## 当前聊天调用流程

```text
用户请求 → Java 校验用户、会话、模型、Agent 和知识范围
→ Java 估算输入及 RAG 上下文，按 requestId 原子预占生成额度
→ RAG 查询另预占 Embedding/Rerank 用量
→ Java 发送签名的 Python 聊天/RAG 请求
→ Python 返回实际模型 usage、正文、引用和唯一终态
→ Java 在终态事务中结算、保存消息/引用及使用记录
```

Java 在调用 Python **之前**预占；Python 不反向请求 Java 预占。普通单轮聊天使用一轮预占，携带 MCP 工具时最多预占四轮模型额度并下发总 Token 上限。Python 将每轮模型输入/输出累计，工具参数和结果进入后续模型上下文产生的 Token 计入实际用量；MCP 工具调用次数本身不扣模型 Token。模型多轮用量缺失或超过请求总预算时不得成功结算。

成功时释放整个预占并按实际可扣额度增加已用额度，记录成功用量和助手消息。失败、取消或超时若尚无已发生用量，则释放全部预占；若模型已经消耗 Token（例如工具调用前一轮已完成），`AiChatTokenServiceImpl.settleFailed` 记录实际输入/输出与失败状态，扣减不超过已预占的额度，并释放其余预占。不能把“失败全部免费”作为规则。结算按 requestId/callId 防重，避免重试或重复终态双扣。

RAG 查询阶段的 Embedding/Rerank 与生成阶段分开预占和结算。入库 Worker 的视觉/Embedding 使用项目知识任务预算，失败事件仍保留失败前已发生用量；具体计量单位和去重键见 [RAG v1 契约](contracts/rag-v1/RAG机器契约说明.md)。

## 并发、权限和安全

有限账户预占必须通过数据库事务及原子余额更新防止并发透支。角色/Agent/模型权限在请求前由 Java 校验；取消权限后新请求不得继续使用模型。超时、连接断开和重复事件只允许一个终态；未消耗的预占应清理。Java/Python 的内部调用使用独立签名，前端不能直接提交扣费数量、用量来源或用户 ID。明细中不保存模型密钥和完整敏感 Prompt。

现行 FIXED/AUTO 共用账户：AUTO 只能在 Java 授权候选中选择模型，预算与审计绑定最终裁定模型。多轮 MCP 工具调用仍属于同一聊天请求，累计后一次结算；如未来引入独立模型调用账本，应维持 requestId 与 callId 的幂等对应。

## 验收重点与后续扩展

检查无权限模型、额度不足、并发请求、无限额账户、成功结算、模型前失败、部分模型用量后工具失败、重复终态、RAG 查询与生成分别结算，以及浏览器断开。当前自动化覆盖 MCP 四轮预占、实际用量、失败部分用量与释放；真实多供应商 usage 字段及目标数据库并发行为仍需环境联调，见 [项目开发进度](项目开发进度.md)。

部门/角色独立额度、周期自动发放、按价格折算与非 Token 单位（图片/音频/视频）是可选后续能力，未纳入当前聊天扣费规则。
