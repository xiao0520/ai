# 聊天上下文与会话设计

> 现行实现核对：2026-09-28。本文描述普通聊天、RAG 与 MCP 接入后的真实上下文构建；跨服务字段以 [RAG v1 契约](contracts/rag-v1/RAG机器契约说明.md)和 Java/Python DTO 为准。旧的 `toolManifest` JSON 草案、`knowledgeScope.libraryIds` 示例和“Python 尚未接入”阶段说明已废弃。

## 数据与职责

`chat_session` 和 `chat_message` 保存会话及展示历史；Java 的会话/消息服务是唯一业务写入方。Token 预占、实际结算和使用明细同样由 Java 管。Python 只接收 Java 本次已授权的模型 Profile、历史消息、执行策略、可选 RAG scope 和可选 MCP 工具清单；不读取业务库、角色表或登录 Token。

当前 `chat_session_summary` 表与摘要 Service 已存在，但主聊天执行链没有自动生成并注入长会话摘要。因此，不能把“自动摘要替代旧消息”写成现行功能；它是后续增强。

## 当前请求流程

1. Java 在仍有登录上下文的请求线程解析聊天模式：`GENERAL` 不加载知识库，`KNOWLEDGE` 校验用户明确选择的单个知识库；随后执行 FIXED/AUTO 模型路由，并计算角色、Agent 与模型能力交集中的 MCP 工具。
2. Java 的 `ChatExecutionServiceImpl` 在执行任务中锁定会话归属，保存用户本轮消息并读取受控数量的历史。历史按模型 `maxInputTokens` 裁剪，当前用户问题和必要系统约束不能被静默丢弃。
3. Java 估算历史与当前问题输入，RAG 时额外计算证据上下文预算和 Prompt 开销，再预占生成额度；RAG 查询 Embedding/Rerank 预算独立预占。有工具时最多预留四轮模型额度。
4. 无可用知识范围走普通聊天请求；有可用范围创建短期授权检索快照并走 RAG 请求。两条请求均可携带同一个可选 `tools` 清单；空清单沿用无工具链。
5. Python 根据请求执行模型生成或 RAG 检索、引用校验和可选 MCP Agent；SSE 只返回受控事件与最终回答，不输出工具参数或中间消息。
6. Java 收到完整 `completed` 后结算实际用量并保存助手消息及合法引用；失败或中断时按已发生用量处理，并释放剩余预占额度。浏览器断开会取消后台执行任务。

不能相信前端传入的 `userId`、模型权限、知识库 ID 或 MCP 工具权限；所有范围都在 Java 重新计算。RAG 的授权候选和引用在完成前复核，引用回访时再次检查会话和资源权限。

## 上下文预算

完整历史留在数据库，模型只接收本次所需的有限消息。Java 根据模型最大输入 Token、历史消息数量和当前问题估算预算；RAG 证据占用独立的上下文额度。工具结果进入下一轮模型上下文时产生的输入 Token 计入该轮实际模型用量；工具调用次数本身不直接等于 Token 用量。若模型多轮未报告完整 usage，工具分支失败，避免漏计费。

当前不承诺语义摘要、无限长上下文或浏览器断线后的 SSE 回放。需要自动摘要时，应定义覆盖消息范围、摘要版本、权限撤回后的失效规则和实际生成费用，再将摘要显式纳入主执行链。

## 契约与检查

Java→Python 普通聊天使用 `PythonChatStreamRequest`；RAG 使用 `RagChatStreamRequest` 和短期 `RagExecutionScope`。请求通过内部 Service Token、HMAC、时间戳和 nonce 签名，密钥不进入消息内容。Python 的 `delta`、`usage`、`citation`、`completed`、`failed` 由 Java 验证终态并转发；具体字段以机器契约和当前代码为准，不在本文复制易过期的 JSON 模板。

涉及上下文、授权范围或结算的变更须覆盖：会话越权、模型权限变化、历史截断、RAG 证据预算、无工具/有工具分支、多轮用量、SSE 单一终态和引用复核。验证命令见 [AI 执行服务开发约束](Python执行服务开发指南.md)与 [MCP 接入验收](MCP接入与验收.md)。
