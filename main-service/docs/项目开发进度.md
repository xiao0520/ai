# MJN AI 项目开发进度

> 最后更新：2026-11-11
> 本文是项目当前完成情况、剩余工作和实施顺序的统一入口。设计细节仍以各专项设计文档为准。

## 1. 项目结构与固定边界

- Java _后端及两个前端位于 main-service，负责用户、权限、会话、模型配置、任务状态、索引发布、预算结算和审计。_
- Python AI 执行服务位于 ai-service，负责模型调用、知识库任务执行以及 RAG 检索与流式回答。
- 普通聊天继续使用 Java → Python 内部 HTTP/SSE，不经过 Kafka。
- Kafka 仅承载知识库后台任务，方向为 Java 发送、Python 消费并回报结果。
- 知识库 ACL 和可检索范围完全由 Java 裁定；创建者不自动放行，暂不增加 USER 授权，继续使用角色/部门 ACL。
- Python 不连接业务 MySQL，不自行推导权限，不保存 Java 业务状态。
- 配置来源已收敛：模型、协议、模态、维度、Token 上限、文档模型绑定和切片参数由管理端数据库持有；`.env`/`application.yml` 只保存部署地址、认证密钥和启用开关，技术默认值由两端类型化配置类校验。
- 管理员在 Java 上传、替换或重新解析文档时选择文档版本的 TEXT/MULTIMODAL 处理模式和模型管理 Profile；Embedding、OCR/视觉随文档处理快照固化。Rerank 只由知识库级检索配置控制并在查询时冻结当前修订；空配置按 Dense-only 默认值执行。
- Python AI/RAG 执行层后续开发以 LangChain 1.x 模块化组件和 Runnable/LCEL 为主；自定义算法通过 LangChain 接口或 Runnable 适配接入同一主链。只有控制面职责、框架无法表达的供应商协议、低层存储生命周期或经验证无法满足安全、审计、流式、异步取消及性能要求时才允许局部例外，且必须在设计和评审记录中说明原因、范围与回接方式。

## 3. 尚未完成

MCP 的管理端账号、实际业务数据库、付费模型与目标第三方 Server 的端到端人工验收尚待完成；自动化与官方测试 Server 验证见 [MCP 接入与验收](MCP接入与验收.md)。

### 3.1 真实环境验收

- 在真实 Embedding、视觉/OCR 模型和真实 Qdrant 上验证 Endpoint、协议兼容、响应维度、计费字段、过滤、超时、取消、写后可查询性及 generation 删除。
- 使用脱敏真实资料验证复杂中文 PDF、DOCX 表格、CSV、XLSX、PPTX、扫描件、超大文件、OCR、XLSX 内嵌图片与图片描述质量；旧版 DOC/XLS/PPT 不纳入支持与验收范围。
- 在真实 MySQL、OSS、Kafka、Qdrant 和模型服务中验证清理、对账补偿、REBUILD 和预算结算。
- 当前阶段继续以代码、单元测试、契约和内存 Qdrant 验证为准，统一在计划功能完成后执行外部服务验收。

### 3.2 RAG 查询与聊天的真实验收

- 第 5 项代码闭环已完成：邻接/父片段补齐、证据选择、上下文预算、ChatPromptTemplate、流式回答、SSE 引用、引用持久化/回访鉴权以及查询/生成用量结算均已接入。
- 用户端只通过现有聊天入口显式选择 `knowledgeId` 使用 RAG；未选择时为 `GENERAL` 普通聊天。按产品决定，不新增 Java 管理端检索测试页面，也不提供通用文档片段查询接口。内部检索测试路由仅用于复用生产检索链和诊断。
- 尚未完成的是第 6 项真实环境验收：真实模型与 Qdrant 的回答质量、引用准确性、权限撤回、计费字段和流式异常行为仍需联调。

### 3.3 聊天模型自动路由的验收边界

- `FIXED` 与首期确定性 `AUTO` 均已实现；Python路由请求只含Java授权候选和路由属性，不含供应商密钥，生成阶段仍只接收Java最终裁定的单个模型Profile。
- Java在路由前过滤权限、状态、可见性、配置和输入长度，在路由后复核候选摘要、模型ID、发布修订、角色权限和Agent权限；候选只有一个时直接选择并记录 `SINGLE_CANDIDATE`。
- 当前AUTO根据视觉、工具、长上下文、代码、推理能力及管理端配置的优先级/成本确定性选择，不额外调用LLM。真实多供应商路由、预算和消息审计仍需在最终环境验收阶段联调。
- Embedding、视觉/OCR 使用索引及文档处理快照，Rerank 使用知识库检索配置；它们都不参与聊天模型 AUTO 路由。
