# RuoYi AI 企业知识库设计与接口规范

> 现行实现核对：2026-09-28。本文描述 Java 管理、ACL、文档/索引版本；入库与查询编排见 [RAG 开发设计](RAG开发设计.md)，机器接口见 [RAG v1 契约](contracts/rag-v1/RAG机器契约说明.md)。

## 1. 结论与边界

本系统的知识库应是公司内部的受权限保护内容资产平台，而不是“上传文件后直接全文搜索”的功能。

Java 控制面负责知识库、文档、OSS 文件归属、角色/部门 ACL、模型发布配置、文档处理方案选择、解析任务、索引版本、检索策略、审计与 Agent 候选范围管理。Java 不执行 OCR、文件解析、Embedding、向量检索、重排或大模型调用。

Python 运行面按 Java 固化的文档处理快照执行文件解析、OCR、切片、Embedding 和向量写入；查询时只按知识库检索配置完成召回、融合、可选 Rerank 和上下文选择。未保存策略的旧知识库按 Dense-only 默认值执行。Python 不自行选择或切换业务模型，不直接读取公司人员、部门、角色、ACL 或业务 MySQL，也不持有 OSS 全局密钥。

> 知识库的 `knowledge_index_version` 必须保留。它是向量索引运行版本，和 MCP 的管理配置发布版本不是同一概念。

```text
员工 / 管理员
    │
    ▼
Java 控制面
    ├─ 知识库、文档、文档版本
    ├─ 角色 / 部门 ACL
    ├─ OSS 文件归属、受控下载
    ├─ 解析任务与索引版本

    └─ 回传进度、片段目录、索引结果
```

## 3. 核心领域模型

```text
知识库 knowledge_info
  ├─ ACL knowledge_acl
  ├─ 索引版本 knowledge_index_version
  ├─ 检索策略 knowledge_info.retrieval_config
  └─ 文档 knowledge_document
       └─ 文档版本 knowledge_document_version
            ├─ OSS 文件 sys_oss
            ├─ 文档处理模式与 Embedding/OCR 发布引用
            └─ 解析任务 knowledge_parse_job
```

### 3.1 知识库

知识库是权限、索引和 Agent 范围的最小管理单位。制度、研发资料、销售资料、项目机密资料应使用不同知识库隔离。

| 字段 | 说明 |
|---|---|
| `id` | 知识库 ID |
| `library_code` | 稳定业务编码，供 Python、日志、导入导出使用 |
| `name` / `description` | 名称与说明 |
| `user_id` | 创建人；仅用于审计和创建人筛选，不作为访问授权依据；平台根账号由 Java 统一身份机制识别 |
| `access_scope` | `ALL_INTERNAL` 或 `ACL_ONLY` |
| `status` | `ENABLED` / `DISABLED` / `DELETED` |
| `splitter_config` | 切片规则快照来源 |
| `current_index_version` | 当前可检索索引版本 |
| `permission_revision` | ACL 变动时递增，用于失效缓存 |

Embedding 的文档处理修订由文档版本及快照承接，命名向量结构由 `knowledge_index_version` 承接；知识库级 `knowledge_info.retrieval_config` 是召回、RRF、阈值及 Rerank 策略的唯一运行来源。旧文档级 Rerank 字段仅保留历史数据可读性。

### 3.2 文档与版本

文档采用“逻辑文档 + 物理版本”模型：

- `knowledge_document`：逻辑文档，例如《员工手册》；
- `knowledge_document_version`：一次上传的物理文件，例如 V1 PDF、V2 DOCX；
- `sys_oss`：实际 OSS 对象；

旧表 `knowledge_attach` 已退役并物理删除。解析片段与命名向量由 Python 写入 Qdrant generation，Java 保存不可变产物清单、索引成员和发布元数据，不以旧 `knowledge_fragment` 表作为检索来源。

替换文件必须创建新的版本，不能覆盖旧 OSS 对象。新版本解析成功并进入目标索引后，才切换文档当前版本。
管理员上传、替换或重新解析文档时选择处理模式及兼容的文本/多模态 Embedding、视觉/OCR Profile。模型来自 Java 模型管理的已发布修订，文档入库重试复用首次处理快照。知识库在每次查询时从 `retrieval_config` 冻结当前 Rerank 修订；空配置按 Dense-only 默认策略读取。

文档级选择受目标索引版本约束：索引版本预先定义 `dense_text`、可选 `dense_vision` 与 `sparse` 等命名向量空间及其维度/距离。不同模型的向量不能写入同一个向量名称；改变向量模型、维度或输入语义时必须构建新索引版本。

OSS 业务路径使用系统参数 `ai.oss.knowledge-attachment.config-key`，例如值为 `knowledge-attachment` 时，对象路径为：

```text
test/knowledge-attachment/{uuid}.pdf
```

### 3.3 文档状态

```text
PENDING       已上传，等待 Python 处理
PROCESSING    正在解析或入库
READY         当前版本已进入目标索引
FAILED        解析或索引失败
DISABLED      管理员停用，不参与检索
DELETED       逻辑删除，等待异步资源清理
```

### 3.4 索引版本

```text
BUILDING  新索引构建中
READY     已完整构建，可切换
ACTIVE    当前在线检索版本
FAILED    构建失败
ARCHIVED  历史版本，延迟清理
```

```text
创建 BUILDING
  → 创建目标文档解析任务
  → Python 写入新向量集合
  → 全部完成后 READY
  → 切换为 ACTIVE
  → 原子更新 knowledge_info.current_index_version
  → 旧 ACTIVE 变为 ARCHIVED
```

单文件新增、替换、重新解析只有在所选文档处理 Profile 与当前 `ACTIVE` 索引的命名向量结构兼容时才可写入；切片规则、Embedding 模型、向量维度、距离或输入语义改变时，必须构建新的完整索引版本。Rerank Profile 修订在查询时从知识库配置冻结；单独变更查询 Rerank 不要求重新解析、重新生成向量或重建 Qdrant 索引。

## 4. 权限与 Agent 关系

### 4.1 当前 ACL

当前授权以角色和部门 ACL 为基础，不以文档创建人自动放行，也不通过 Agent 扩权。

| 主体 | 用途 |
|---|---|
| `ROLE` | 主授权方式，复用公司角色 |
| `DEPT` | 部门资料库，可设置是否覆盖下级部门 |
| `ALL_INTERNAL` | 全体已登录员工可读，由 `access_scope` 表示 |

权限等级：

| 权限 | 含义 |
|---|---|
| `READ` | 可检索、查看引用、下载受控源文件 |
| `WRITE` | 可上传、替换、重新解析文档 |
| `MANAGE` | 可维护 ACL、索引策略、删除知识库 |

规则：多个角色、部门的权限取并集；不做显式 `DENY`；部门授权是否覆盖下级部门由 ACL 的 `include_children` 控制。创建者不自动获得 READ、WRITE 或 MANAGE 权限，列表范围与单资源检查均不得按 user_id 放行。ALL_INTERNAL 只赋予读取权限，写入和管理仍需相应授权。

Java 是资源权限的唯一裁定方，管理、文档读取、RAG 检索和引用访问复用统一授权规则。普通用户不能访问停用知识库；平台根账号保留管理停用资源的既有能力，逻辑删除资源不进入正常访问范围。RAG 还须由 Java 在 READ 授权基础上检查库/文档状态、发布版本与 ACTIVE 索引，任何身份都不能将停用、删除或未发布内容用于回答。Python/LangChain 只执行 Java 下发的可检索范围，不建立独立权限规则。

取消创建者特权后，无 ACL 的 ACL_ONLY 知识库不会因创建人身份出现在员工的可访问列表中。平台根账号应按角色或部门显式分配权限；不为历史创建者自动补授权，以免恢复已移除的隐式权限。

### 4.2 Agent 不是授权主体

`agent_knowledge` 仅表达 Agent 的候选范围：

- `ROLE_AUTHORIZED`：Agent 可使用员工有 `READ` 权限的全部知识库；
- `LIMITED_BINDING`：只能使用 Agent 已绑定知识库与员工有效权限的交集；
- Agent 配置绝不能增加员工的知识库权限。

```text
最终可检索范围
= Agent 候选范围
∩ 角色与部门授权范围
∩ 知识库已启用
∩ 索引版本为 ACTIVE
```

## 5. Java 管理端功能

```text
知识库管理
├─ 知识库列表
├─ 文档管理
├─ 权限管理（建议嵌入知识库详情）
├─ 解析任务
├─ 索引版本
├─ 检索策略（召回/RRF/上下文）
└─ 使用统计与任务诊断（按现行页面提供）
```

当前管理与执行行为：

1. 管理员可新增、编辑、启停、逻辑删除知识库。
2. 只有拥有 `WRITE` 的员工才能上传、替换、重新解析文档。
3. 上传、替换或重新解析时选择 `TEXT`/`MULTIMODAL` 处理模式及目标索引允许的 Embedding、OCR/视觉 Profile；Java 保存文档版本与执行快照，创建 Kafka 入库任务。Rerank 只使用知识库查询策略。
4. 可查看任务、取消、重试和失败原因。
5. 可查看解析任务、索引版本与检索策略；内部检索测试链路已接入 Python，用户问答使用现有聊天入口。
6. 私有 OSS 文件只能走 Java 权限校验后的下载接口或短期预签名 URL，不能直接打开原始 OSS URL。

管理端的检索策略与索引状态必须反映当前 Java 配置和发布结果；具体页面以现行前端实现为准，不把历史“待运行端接入”提示当作功能状态。

## 6. Java 管理接口（现行）

管理接口以 `KnowledgeLibraryController`、`KnowledgeDocumentController`、`KnowledgeParseJobController` 和 `KnowledgeIndexVersionController` 为准。下表只列主要入口，具体参数和权限以 Controller 与服务层校验为准。

| 资源 | 现行路径与动作 |
| --- | --- |
| 知识库 | `GET/POST /knowledge/libraries`、`GET/PUT /knowledge/libraries/{id}`、状态和删除接口 |
| 检索策略 | `GET/PUT /knowledge/libraries/{id}/retrieval-config` |
| 文档 | `GET /knowledge/libraries/{knowledgeId}/documents`、`POST /knowledge/libraries/{knowledgeId}/documents/upload`、版本、重新解析、状态、删除和受控下载 |
| 任务 | `GET /knowledge/jobs`、`POST /knowledge/jobs/{id}/retry`、`POST /knowledge/jobs/{id}/cancel` |
| 索引版本 | `GET/POST /knowledge/index-versions`、`POST /{id}/activate`、`POST /{id}/rebuild`、`DELETE /{id}` |

上传、替换和重新解析按 Java 已发布 Profile 与目标索引快照校验 `TEXT` / `MULTIMODAL` 模式、Embedding 和视觉/OCR 模型；查询时 Rerank 只由知识库检索配置决定。前端不提交模型地址、密钥、任意发布修订或 Qdrant 向量名称。

索引版本的成员、任务与当前指针由 Java 复核。空的 `ACTIVE` 版本允许在行锁内清空当前指针后删除；仍有文档成员或运行任务时拒绝。向量与 OSS 清理由精确 generation 的异步维护任务完成。

## 7. Python 任务通道与内部接口

Python 不访问业务 MySQL，不持有 OSS AccessKey/SecretKey。知识库任务使用 Kafka 调度，受控文件、执行快照、候选复核和产物验收使用统一内部签名的 HTTP 接口。原 claim/heartbeat/complete/failed 轮询接口及其 DTO 已删除。

| 类型 | 契约或路径 | 说明 |
|---|---|---|
| Kafka command | `knowledge.ingestion.command.v1` | Java Outbox 下发知识库执行批次 |
| Kafka result | `knowledge.job.result.v1` | Python 回报开始、进度、产物就绪、失败或取消 |
| Kafka control | `knowledge.job.control.v1` | Java 广播取消 |
| Kafka DLQ | `knowledge.dlq.v1` | 不可处理消息进入运维补偿 |
| HTTP | `/internal/knowledge/jobs/{id}/artifact-tickets` | 已实现；签发任务绑定的受控票据 |
| HTTP | `/internal/knowledge/scopes/{snapshotId}/manifest-pages` | 已实现；分页读取授权范围内成员 |
| HTTP | `/internal/knowledge/scopes/{snapshotId}/validate-candidates` | 已实现；按当前权限复核候选 |

Kafka command 和 result 必须绑定 jobId、requestId、attemptId、generationId、executorId 及序列/摘要字段。Java 必须拒绝旧批次、错误执行所有者、过期租约、错误索引版本和重复冲突序列。正式发布前仍须校验不可变产物清单、向量计数、维度、来源和当前发布意图。

## 8. 数据库设计与 SQL

### 8.1 表职责

| 表 | 职责 |
|---|---|
| `knowledge_info` | 知识库主数据与当前 ACTIVE 索引指针 |
| `knowledge_document` | 逻辑文档 |
| `knowledge_document_version` | 文档物理版本、OSS 文件元数据、处理模式及 Embedding/OCR/Rerank 模型发布引用 |
| `knowledge_acl` | 角色、部门 ACL |
| `knowledge_parse_job` | Java 控制面任务、执行批次、租约与结果状态 |
| `knowledge_index_version` | 向量索引版本、命名向量结构及允许的模型兼容约束 |
| `knowledge_info.retrieval_config` | 知识库级召回、RRF、阈值、上下文及 Rerank 策略 JSON |
| `agent_knowledge` | Agent 候选范围，不是权限表 |

### 8.2 必要字段调整

- `knowledge_info`：保留 `library_code`、`user_id`、`access_scope`、`description`、`splitter_config`、`current_index_version`、`permission_revision`、`retrieval_config` 与审计字段；不保留旧散列检索参数、`share`、部门归属和发布修订字段。
- `knowledge_acl`：`subject_type` 支持 `ROLE`、`DEPT`；增加 `include_children`、`effective_time`、`expire_time`。
- `knowledge_document_version`：记录 `oss_id`、文件哈希、MIME、大小、版本号、processing_mode、文本/多模态/OCR/Rerank 模型 Profile ID 与发布修订、Rerank 路由模式、解析状态和失败原因。
- `knowledge_parse_job`：增加 `document_id`、`document_version_id`、`idempotency_key`、`lease_owner`、`lease_expire_time`，并保存首次固化的文档处理快照和索引快照；传输重试复用同一快照。

旧清理脚本已退役；当前表结构以完整初始化脚本 [`ruoyi-ai.sql`](script/sql/ruoyi-ai.sql) 和 `script/sql` 下的增量迁移为准。

执行顺序：备份数据库 → 核对并执行适用的增量迁移 → 部署新版 Java 控制面与前端 → 重新登录并验证知识库、ACL、文档、解析任务、索引版本页面。新版前端已提供知识库列表、文档与版本、ACL、解析任务、索引版本及检索策略管理；片段/向量存在 Qdrant，不另建旧式关系库片段目录。

## 9. 删除、替换与任务状态

### 替换文件

```text
上传 V2 → 创建 V2 版本(PENDING) → 创建解析任务
→ Python 完成 V2 入库 → 切换当前文档版本 → 旧版本 ARCHIVED
```

### 删除文档

```text
文档标记 DELETED → Java 立即从检索范围排除
→ 创建资源清理任务 → Python 删除向量 → 归档或删除 OSS 对象
```

不能沿用“直接删除 OSS 和 MySQL 片段”的方式，否则会留下向量孤儿数据，且无法重试恢复。

任务状态：

```text
PENDING → RUNNING → SUCCEEDED
                └→ FAILED → RETRY_WAIT → RUNNING
PENDING / RUNNING → CANCELLED
```

Java 根据 `lease_expire_time` 回收超时的 `RUNNING` 任务，防止 Python 进程异常导致任务永久卡住。

## 10. 管理端验收与现行执行链

1. 员工只能看见自己角色或部门有权限的知识库。
2. Agent 不能让员工访问未授权知识库。
3. 文件、文档版本、任务、索引版本、片段目录均可追溯。
4. 文档替换不影响旧线上索引，直到新版本成功。
5. 删除文档后不会继续出现在检索范围和引用中。
6. Python 接入时不需要读取公司人员表，也没有 OSS 全局密钥。
7. Java 全程不执行模型调用、Embedding 或向量检索。
