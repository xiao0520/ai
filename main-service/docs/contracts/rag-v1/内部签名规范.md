# Java 与 Python 统一内部签名契约

状态：签名规范、Java 发送端、Python 入站验签、Python 出站签名及 Java 验签组件已实现。普通聊天、RAG 聊天及 Python→Java 的受控资源/候选复核接口已使用该规范。修订任何签名字节规则时必须同时更新测试向量和双端实现。

## 适用路径

- Java → Python 的 /internal/ai/... HTTP 接口统一使用本规范。
- Python → Java 的 /internal/knowledge/... HTTP 接口统一使用本规范。
- /internal/ai/v1/chat/stream 中的 v1 是业务 API 路径版本，不代表另一种签名算法。
- 缺少版本头或签名组件时直接拒绝，不回退到历史签名规则。
- 凭证由调用方向确定。算法保持一致，两方向可以配置独立服务 Token 和签名密钥，以区分服务身份并缩小密钥泄露影响范围。
- Kafka 消息不使用 HTTP 签名，依靠 Broker 身份认证、Topic ACL 和消息级业务幂等。

## 请求头

| 请求头 | 格式 |
|---|---|
| X-AI-Service-Token | 对应调用方向的服务身份 Token；不进入日志 |
| X-AI-Signature-Version | 固定字符串 2，用于标识当前唯一线上字节格式并阻止降级 |
| X-AI-Timestamp | UTC Unix 秒，十进制非负整数；不接受浮点、指数、正负号 |
| X-AI-Nonce | 16～128 位 ASCII 字母、数字、下划线或连字符；建议 UUID |
| X-AI-Signature | HMAC-SHA256 的 64 位小写十六进制字符串 |
| Content-Type | application/json |

固定版本值 2 只是传输协议标识。代码不再保留历史算法、兼容分支或第二套配置。

## 规范路径

首期内部签名只允许 POST。路径字符限定为 ASCII 字母、数字、下划线、连字符和斜杠。

发送方使用接收方内部路由的绝对路径，例如 /internal/ai/v1/chat/stream 或 /internal/knowledge/jobs/101/artifact-tickets；不包含域名、端口和代理前缀。接收方必须使用实际路由路径验签。

拒绝查询串、百分号编码、反斜杠、空段、点段和尾斜杠。路径不转小写、不重新编码、不自动去尾斜杠。请求 ID、游标和票据放在 JSON body 中。

## 待签名字符串

bodyDigest = SHA256(rawBodyBytes) 的小写十六进制值。

以下六项按顺序使用单个 LF（0x0A）连接，结尾不增加换行；整个字符串使用 UTF-8：

~~~text
2
POST
规范路径
X-AI-Timestamp 原文
X-AI-Nonce 原文
bodyDigest
~~~

signature = hex_lower(HMAC_SHA256(signingKeyUtf8, canonicalBytes))。

JSON 只能序列化一次，发送与摘要计算必须使用同一份 UTF-8 字节。接收端对原始 body 验签，不得解析并重排 JSON 后验签。

## 验证顺序与防重放

1. 限制请求体大小，检查方法、路径、查询串、固定版本头和其余头部格式。
2. 使用恒定时间比较调用方向对应的服务 Token。
3. 校验时戳与服务端当前时间差不超过配置窗口。
4. 对完整原始 body 计算摘要并验签。
5. 验签成功后原子占用 nonce。多实例接收端必须使用共享存储。
6. nonce 至少保留到 timestamp + window。
7. 再校验任务、attempt、执行者、授权快照和业务幂等约束。
8. 认证失败只返回稳定授权错误，不泄露密钥、签名或原始正文。

重试必须生成新的 timestamp、nonce 和 signature，同时保留业务 requestId、attemptId 和内容摘要。传输防重放与业务幂等是两个独立边界。

## 测试向量

[internal-signature-vectors.json](internal-signature-vectors.json) 只包含公开假密钥和合成 body。rawBody 解码后的文本再编码为 UTF-8，得到待发送字节。expectedBodySha256、canonical 和 expectedSignature 是期望值。

~~~powershell
& ai-service/.venv/Scripts/python.exe main-service/docs/contracts/rag-v1/verify_signature_vectors.py
~~~

Python 和 Java 均使用这些向量测试相同的规范字节。Java 验证器通过 Redis 原子占用 nonce；Python 当前聊天接收端使用进程内 nonce 存储，扩展为多实例部署前必须切换到共享存储。
